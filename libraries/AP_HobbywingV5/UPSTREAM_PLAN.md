# Upstream contribution strategy: ArduPilot stable readiness

## Goal and claim boundaries

Aim for **upstream merge into ArduPilot master**, followed (only at maintainers' discretion and according to ArduPilot's release process) by inclusion in a future official stable release. A successful fork build, branch or PR does **not** mean upstream acceptance or stable availability.

## Incremental PR sequence (subject to maintainer feedback)

1. RFC/issue: outline serial-port ownership, telemetry-only design, measured ESC behavior and non-Datalink V2 scope.
2. Protocol decoder + host tests + provenance; no board behavior changes.
3. Serial backend and AP_ESC_Telem standard field integration, feature-gated and with SITL support.
4. Optional BEC and fault exposure (logging/MAVLink), preferably in a separate PR with API review.
5. Documentation for user-facing `SERIALx` parameters, supported models, electrical wiring caveats, diagnostics and limitations.

## Acceptance matrix

| Area | Required evidence |
|---|---|
| Coding | ArduPilot formatting, reviewable diff, no unrelated changes, clear copyright/GPL attribution |
| Protocol | Golden frames, valid CRC, invalid CRC, framing loss, timeout, fuzz and endian tests |
| Build | Pixhawk 4 target, default no-feature builds, SITL, CI results and flash/RAM delta |
| Function | Valid voltage/current/ESC temp/RPM with timestamps and correct stale behavior |
| RPM | Verified electrical-vs-mechanical interpretation with motor pole count and independent sensor |
| Extended telemetry | BEC fields and faults only where physically reported; correct labeling/transport |
| Regression | Existing BLHeli/serial-16 path unaffected, no double-reader UART ownership |
| Safety | Motor/throttle control unchanged, arm/disarm/failsafe unaffected, no writes to ESC |
| Hardware | Real 80A V5 capture, tested power sequences, cable diagram, reproducible logs |
| Documentation | Parameter docs, board-independent description, limitations, mission planner screenshots as evidence |
| Compatibility | Explicitly separate untested Platinum 150A V5.1; no unsupported claims |
| Review | ArduPilot maintainer feedback addressed, DCO/contribution rules followed where required |

## Stable-release submission checklist

- [ ] Reference upstream branch/commit and compare fork divergence.
- [ ] Record Rotorflight license/version and preserve applicable copyright.
- [ ] Pin golden test vectors generated by known Rotorflight simulator version AND separately capture hardware-derived vectors.
- [ ] Demonstrate no runtime writes, no serial-port conflicts.
- [ ] Host unit tests pass and reproduce in documented environment.
- [ ] SITL tests pass and capture data.
- [ ] Pixhawk 4 build passes and boot/use data available.
- [ ] Hardware captures show decoded values matching external measurements.
- [ ] Existing motor controller behavior and independent RPM sensor unchanged.
- [ ] Documentation updated for user settings and electrical integration.
- [ ] ArduPilot maintainers accept architecture before extensive feature growth.
- [ ] Upstream PR reviewed/merged; official stable release inclusion independently verified.

## Known risks

Proprietary undocumented ESC quirks, passive telemetry during startup, half-duplex line electrical interface, diversity between Platinum V5 and V5.1, serial port contention, BEC field placeholders, current bias/throttle-zero handling, log/MAVLink field availability and potential upstream architectural objections.

Keep proof and failure cases visible; do not declare the driver stable based on one successful bench run.
